# 「拾光集」部署文档

> **面向**：负责服务器、发布、运维的同学
>
> **当前决策**：Linux 单机 + Docker Compose + 容器 MySQL 8.4；暂时没有域名和备案，先用「公网 IP + HTTP」；后续再补域名与 HTTPS。

---

## 1. 部署目标与决策

| 项 | 决策 |
|---|---|
| 服务器 | Linux（Ubuntu 22.04/24.04 或其他主流发行版） |
| 容器 | Docker Engine 24+ + Docker Compose v2 |
| 应用形态 | 前端 Nginx 静态站点 + Spring Boot 后端 + MySQL 8.4 容器 |
| 数据库 | 先用 Docker MySQL 8.4 LTS + 数据卷；暂不购买 RDS |
| 访问方式 | 公网 IP + HTTP 80，暂无域名/备案 |
| HTTPS | 后续有域名/备案后补 Caddy 或 Nginx + certbot |
| 数据库迁移 | Flyway，后端启动时自动执行 `db/migration` |
| 数据目录 | `/data/shiguangji`（上传、备份），MySQL 使用 Docker named volume |
| 部署目录 | `/opt/shiguangji/app`（git 仓库） |

### 为什么先用 Docker MySQL

- 零额外费用，适合课程阶段和单机部署
- 后端与数据库在 Docker 内网，延迟低
- 后续迁移云数据库 RDS 时，只需要改 `DB_HOST / DB_USERNAME / DB_PASSWORD` 并导入备份，代码和 Flyway 不变

代价：备份、磁盘、版本升级、故障恢复由我们自己负责，所以必须配置每日备份并演练恢复。

## 2. 部署架构

```
Internet
   │  HTTP :80（暂无域名，直接 IP 访问）
   ▼
┌─────────────────────────────────────────────┐
│ Docker Compose: shiguangji                  │
│                                             │
│  frontend (nginx:1.27-alpine) :80           │
│    ├─ /            静态 SPA（dist）          │
│    ├─ /api/*       proxy → backend:8080     │
│    └─ /uploads/*   alias → /data/uploads    │
│                                             │
│  backend (eclipse-temurin:17) :8080         │
│    └─ Spring Boot + Flyway                  │
│                                             │
│  mysql (mysql:8.4) :3306（仅内网）           │
│    └─ volume: mysql-data                    │
└─────────────────────────────────────────────┘
   │
   └─ 宿主机目录 /data/shiguangji/uploads（前后端共享）
      /data/shiguangji/backups（备份）
```

对外只开放 **22（SSH）和 80（HTTP）**；3306、8080 不对公网暴露。

## 3. 服务器准备

### 3.1 规格建议

| 项 | 最低 | 建议 |
|---|---|---|
| CPU | 2 核 | 2–4 核 |
| 内存 | 2 GB | 4 GB（MySQL + JVM） |
| 磁盘 | 40 GB | 60 GB+ |
| 系统 | Ubuntu 22.04/24.04 | Ubuntu 24.04 LTS |

### 3.2 安装 Docker

按 Docker 官方文档安装 Docker Engine 和 Compose 插件，不要只安装 Docker Desktop（服务器无桌面环境）。

验证：

```bash
docker --version
docker compose version
```

国内服务器如果拉取 Docker Hub 镜像很慢，在 `/etc/docker/daemon.json` 配置镜像加速，然后重启 Docker。镜像加速地址以云厂商当前提供的为准。

### 3.3 防火墙 / 安全组

只放行：

- 22/tcp（SSH）
- 80/tcp（HTTP）

不要放行 3306、8080。云服务器同时要在安全组里配置。

## 4. 目录规划

```bash
/opt/shiguangji/app                  # git 仓库（当前项目）
/data/shiguangji/uploads             # 用户上传图片（宿主机目录）
/data/shiguangji/backups             # 数据库/上传备份
```

```bash
mkdir -p /opt/shiguangji /data/shiguangji/uploads /data/shiguangji/backups
```

后端容器以 UID `10001` 运行，上传目录需要给它写权限：

```bash
chown -R 10001:10001 /data/shiguangji/uploads
```

## 5. 环境变量

生产配置在 `backend/src/main/resources/application-prod.yml` 中通过环境变量读取；Compose 从 `deploy/.env` 读取。

复制模板：

```bash
cd /opt/shiguangji/app/deploy
cp .env.example .env
chmod 600 .env
```

填写：

| 变量 | 说明 | 示例/生成方式 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，仅运维/备份用 | `openssl rand -base64 32` |
| `MYSQL_DATABASE` | 数据库名 | `shiguangji` |
| `MYSQL_USER` | 应用数据库账号 | `shiguangji` |
| `MYSQL_PASSWORD` | 应用数据库密码 | `openssl rand -base64 32` |
| `JWT_SECRET` | JWT 签名密钥 | `openssl rand -base64 48` |
| `APP_BOOTSTRAP_ENABLED` | 首次启动是否创建管理员 | `true` |
| `APP_ADMIN_USERNAME` | 初始管理员用户名 | `admin` |
| `APP_ADMIN_PASSWORD` | 初始管理员密码 | 自定义强密码 |
| `DATA_DIR` | 宿主机数据父目录 | `/data/shiguangji` |

注意：

- `.env` 含真实密码，**不提交 Git**（根 `.gitignore` 已忽略 `.env`）
- 密码中如含 `$`、空格等特殊字符，Compose 插值可能出问题，建议使用字母数字随机串
- 管理员 bootstrap 代码依赖后端基础层，接口实现后生效；当前后端仍是骨架

## 6. 首次部署步骤

### 6.1 拉取代码

```bash
cd /opt/shiguangji
git clone https://github.com/zxjcw/sh-trade.git app
cd app
```

如果 GitHub 访问慢，可以在本地/CI 构建镜像再推送到镜像仓库，服务器只负责拉取。

### 6.2 准备目录与配置

```bash
mkdir -p /data/shiguangji/uploads /data/shiguangji/backups
chown -R 10001:10001 /data/shiguangji/uploads

cd deploy
cp .env.example .env
chmod 600 .env
vi .env
```

### 6.3 构建并启动

```bash
cd /opt/shiguangji/app/deploy
docker compose --env-file .env -f docker-compose.prod.yml up -d --build
```

首次会：

1. 拉取 MySQL 8.4、Maven、Node、Nginx、JRE 镜像
2. 构建后端 jar 和前端 dist
3. 启动 MySQL，等待健康检查
4. 启动后端，Flyway 执行 `V1__schema.sql`、`V2__seed.sql`
5. 启动前端 Nginx，监听 80

### 6.4 验证

```bash
docker compose -f docker-compose.prod.yml ps

# 后端启动与 Flyway
docker compose -f docker-compose.prod.yml logs -f --tail=200 backend

# 前端
curl -I http://服务器公网IP/

# Flyway 历史
docker compose -f docker-compose.prod.yml exec mysql \
  sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SELECT installed_rank, version, description, success FROM shiguangji.flyway_schema_history;"'
```

看到 V1、V2 的 `success=1` 即迁移完成。

> 当前后端只有启动骨架，没有业务接口；此时部署完成的是基础设施，不是可交易系统。接口实现后前端才能真正登录、浏览和下单。

## 7. 部署文件说明

| 文件 | 作用 |
|---|---|
| `backend/Dockerfile` | 多阶段构建：Maven 打包 → JRE 运行；非 root UID 10001 |
| `frontend/Dockerfile` | Node 构建 → Nginx 托管静态文件 |
| `frontend/nginx.conf` | SPA history 路由、`/api` 反向代理、`/uploads` 静态文件、安全响应头 |
| `deploy/docker-compose.prod.yml` | MySQL、后端、前端三个服务；内网网络、健康检查、日志轮转 |
| `deploy/.env.example` | 生产环境变量模板 |
| `deploy/backup.sh` | 数据库 + 上传文件备份，自动清理旧备份 |

### 7.1 端口

- 前端：`80:80`
- 后端：不映射端口，只在 `backend-net` 内被 Nginx 访问
- MySQL：不映射端口，只在 `backend-net` 内被后端访问

### 7.2 数据卷

- `mysql-data`：MySQL 数据，Docker named volume
- `${DATA_DIR}/uploads`：上传图片，后端可写，前端 Nginx 只读
- 备份放 `${DATA_DIR}/backups`，建议再同步到对象存储或另一台机器

## 8. 数据库与 Flyway

- 迁移脚本：`backend/src/main/resources/db/migration/`
- 生产只执行 `V1__schema.sql`、`V2__seed.sql`；演示数据不要在线上执行
- 已执行脚本不能修改；变更新增 `V3__...sql`
- 生产配置 `clean-disabled=true`、`validate-on-migrate=true`
- 升级前必须先备份数据库

当前验证环境是 MySQL 8.4，Flyway 会提示“8.4 未测试，最高支持 8.1”。处理方式：

1. 上线前把 `flyway.version` 升到支持 MySQL 8.4 的版本，并重新跑迁移测试；或
2. 生产 MySQL 固定 8.0 LTS

## 9. 备份与恢复

### 9.1 手动执行

```bash
chmod +x /opt/shiguangji/app/deploy/backup.sh
/opt/shiguangji/app/deploy/backup.sh
```

输出：

```
/data/shiguangji/backups/db-2026-11-24-030000.sql.gz
/data/shiguangji/backups/uploads-2026-11-24-030000.tar.gz
```

### 9.2 定时任务

```bash
crontab -e
```

加入：

```cron
0 3 * * * /opt/shiguangji/app/deploy/backup.sh >> /var/log/sgj-backup.log 2>&1
```

保留天数由 `BACKUP_RETENTION_DAYS` 控制，默认 14 天。

### 9.3 恢复

```bash
cd /opt/shiguangji/app/deploy

# 数据库
gunzip < /data/shiguangji/backups/db-2026-11-24-030000.sql.gz | \
  docker compose -f docker-compose.prod.yml exec -T mysql \
  sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'

# 上传文件
tar -xzf /data/shiguangji/backups/uploads-2026-11-24-030000.tar.gz -C /data/shiguangji
chown -R 10001:10001 /data/shiguangji/uploads
```

**必须演练一次恢复**，只备份不恢复等于没有备份。

## 10. 升级与回滚

### 10.1 升级

```bash
cd /opt/shiguangji/app
/opt/shiguangji/app/deploy/backup.sh

git pull

cd deploy
docker compose --env-file .env -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml logs -f --tail=100 backend
```

确认 Flyway 新版本迁移成功、页面可用后再结束。

### 10.2 回滚

- 应用代码回滚：`git checkout` 到上一个版本，重新构建启动
- 数据库回滚：Flyway 不写 down 迁移；必须用升级前备份恢复
- 镜像回滚：如果使用镜像仓库，给每次发布打 tag，回滚时改 tag 再 `up -d`

## 12. 后续补 HTTPS

当前没有域名/备案，只能 IP + HTTP。**HTTP 下密码和 JWT 明文传输，仅适合课程演示**。

有域名后：

### 方案 A：Caddy 自动证书

- 新增 Caddy 容器监听 80/443
- 前端容器改为 `127.0.0.1:8081:80`，只让 Caddy 访问
- Caddyfile：

```caddyfile
你的域名 {
    encode gzip zstd
    reverse_proxy frontend:80
}
```

- 域名解析到服务器 IP；大陆服务器需要 ICP 备案
- 开启 HSTS（确认全站 HTTPS 后）

### 方案 B：宿主机 Nginx + certbot

- 宿主机 Nginx 终止 TLS
- 反向代理到 `127.0.0.1:8081`
- certbot 自动续期

## 14. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker pull` 超时 | Docker Hub 网络问题 | 配镜像加速，或用云厂商镜像仓库 |
| Maven/npm 构建很慢 | 服务器访问中央仓库慢 | 配 Maven/npm 镜像，或在 CI 构建镜像后推送 |
| MySQL 容器反复重启 | 密码变量为空/特殊字符/卷权限 | `docker compose logs mysql`，检查 `.env` |
| 后端启动失败 | 数据库未就绪、Flyway 脚本错误 | 看 backend 日志；确认 MySQL healthy；不要改已执行脚本 |
| 页面 502 | 后端未启动或崩溃 | `docker compose ps`、backend 日志 |
| 上传图片 404/403 | 卷未挂载或目录权限不对 | 检查 `/data/shiguangji/uploads` 和 UID 10001 |
| Flyway checksum mismatch | 修改了已执行脚本 | 恢复原脚本；新增 V3 做变更；开发库可删库重跑 |
| 磁盘满 | 日志、备份、上传文件堆积 | 清理旧备份，限制日志，扩容 |
| 时间不对 | 容器时区 | 已设置 `TZ=Asia/Shanghai`、MySQL `+08:00` |

## 15. CI/CD 规划

当前先提供 GitHub Actions 的 CI：

- 后端：JDK 17 + `mvn test`
- 前端：Node 20 + `npm ci` + `npm run build`

后续可扩展：

1. 构建后端/前端镜像并推送到镜像仓库（GHCR / 阿里云 ACR）
2. 服务器通过 SSH 拉取镜像并 `docker compose up -d`
3. 发布前自动备份数据库
4. 发布后探活检查

在服务器直接构建镜像也可以，但更推荐“CI 构建、服务器只拉取”，避免服务器承担编译压力。
