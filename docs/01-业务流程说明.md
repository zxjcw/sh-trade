# 「拾光集」业务流程说明（可行性研究版）

> **用途**：报告第 1 章 1.2.1「业务流程图」的文字依据，回答四件事——谁、在什么情况下、做什么、得到什么。
> **范围**：描述每条业务的触发、流程、结果与关键数据读写；完整字段、外键与约束见《数据存储清单与业务对照.md》。
> **角色**：学生（买家与卖家为同一账号）｜平台运营｜学校管理员。

---

## 1. 总体业务框架

```
注册/登录 → 学籍认证 → 发布物品 → 人工审核 → 上架
   → 浏览 / 求购 / 置换 → 下单 → 托管支付
   → 交付（面交 / 自提点） → 确认收货 → 放款 + 履历 + 信用 → 评价
                     ↘ 退款 / 售后 → 运营仲裁
```

平台围绕两条线运行：**一件唯一物品的流转**（在售 → 已锁定 → 已完成）和**一笔钱的托管释放**（支付 → 托管 → 放款或退款）。物品履历就是这两条线的存档。

## 2. 三个核心机制

- **物品履历**：每件物品一份可查记录，成交后由系统自动追加，用户不能修改——解决"不敢买"；
- **资金托管**：买家付款后钱不进卖家账户，确认收货才放款——解决"不敢付"；
- **信用与评价分离**：信用记录履约行为，评价只影响展示——解决"不敢信"。

## 3. 业务流程清单（14 条）

需要注意的是，以下过程涉及封装，如已有业务封装且在下一个业务中被使用，则不会刻意提出被封装业务中涉及的表
换言之，列举表格仅为重点涉及表格，不列举不代表未涉及

### F1 注册与登录
- **触发**：新用户注册，或已有账号用户登录。
- **过程**：新用户进入注册页，填写用户名、密码、昵称、联系方式等基本信息并提交 → 系统读用户表校验用户名是否已存在 → 不存在则创建账号（角色=学生、认证状态=未认证），写入用户表 → 已有账号输入用户名与密码登录，系统读用户表校验密码哈希 → 登录成功后读用户表判断认证状态：已认证进入平台，未认证或驳回引导进入 F2 学籍认证。
- **结果**：进入平台；未认证用户仅可浏览。
- **表格**: 用户表
- **提示**: 1.新注册的账号不自动绑定学号，学号在 F2 认证时绑定
            2.注册需填写全部基本信息；用户名全局唯一，密码不做唯一性约束
            3.注册时读用户表（校验用户名），通过后写用户表（新增账号）
            4.登录时读用户表（用户名 + 密码哈希）
            5.登录后读用户表（认证状态），未认证或驳回转 F2

### F2 学籍认证
- **触发**：首次登录且未认证或认证被驳回，或未认证用户使用发布、下单、求购、置换等受限功能时。
- **过程**：用户进入认证页，填写学号、姓名、学院、专业、年级并提交 → 系统读学籍表按学号比对姓名与学院等信息 → 核验通过：写认证记录表（核验结果=通过、核验时间），写用户表（认证状态=已认证、绑定学号），写通知表（认证结果）→ 核验不通过：写认证记录表（核验结果=驳回），写用户表（认证状态=驳回），提示原因，可重新提交。
- **结果**：通过后更新用户状态、更新认证记录状态、通知用户并获得发布、下单、求购、置换等资格；未通过可重新提交。
- **表格**: 学籍表、用户表、认证记录表、通知表
- **提示**: 1.同一用户每次提交认证生成一条新记录（保留历史），不覆盖旧记录
            2.认证记录在学籍表比对完成后写入，核验前不落库
            3.核验时读学籍表；核验后写认证记录表（结果/时间）
            4.通过后写用户表（认证状态、学号）与通知表（认证结果）
            5.未通过写用户表（认证状态=驳回）并写认证记录表，可重新提交
            6.一个学号只能绑定一个账号

### F3 物品发布与履历建档
- **触发**：已认证卖家发布物品。
- **过程**：卖家进入发布页，读分类表选择分类 → 填写标题、原价、入手价、成色、描述、来源、笔记标签 → 上传图片并标记首图（写物品图片表，状态=有效）→ 提交后系统生成物品编号，写物品表（状态=待审核）→ 运营审核（F12；本业务只承接审核结果）→ 审核通过：写物品表（状态=在售、上架时间），系统写履历记录表首条「建档」→ 审核驳回：写物品表（状态=驳回）。
- **结果**：提交后进入「待审核」；审核通过后上架，并由系统写入对应物品履历首条「建档」；不通过则驳回给卖家修改。
- **表格**: 物品表、分类表、物品图片表、履历记录表
- **提示**: 1.发布时读分类表（供选择），写物品表（待审核）与物品图片表（含首图，图片状态=有效）
            2.审核通过后写物品表（在售、上架时间）、履历记录表（建档），审核结果通知由 F12 写
            3.审核驳回写物品表（驳回），驳回通知由 F12 写
            4.审核记录由 F12 写，F3 只写"结果"，不重复写两张主表
            5.每件物品仅一张首图；履历首条只由系统写入

### F4 浏览、搜索与筛选
- **触发**：用户寻找物品。
- **过程**：用户进入首页或搜索页，读分类表选择分类、输入关键词，设置筛选与排序 → 系统读物品表检索状态=在售的物品，读物品图片表（仅状态=有效）取缩略图，返回列表 → 用户点击物品，读物品表、物品图片表（仅状态=有效）、履历记录表、用户表（卖家认证与信用）展示详情 → 用户可收藏（写收藏表），或求购/置换/下单，转入对应业务 → 未认证用户点击购买时读用户表判断认证，提示先认证。
- **结果**：可收藏、求购、置换或下单；未认证用户仅可浏览。
- **表格**: 物品表、物品图片表、履历记录表、用户表、分类表、收藏表
- **提示**: 1.分类导航读分类表；检索读物品表（仅取状态=在售）
            2.查看详情读物品表、物品图片表（仅有效图）、履历记录表、用户表（卖家信息）
            3.收藏时写收藏表；详情页不读收藏表（不显示已收藏状态）
            4.进入下一步操作前读用户表判断是否认证
            5.评价不在详情页展示，F4 不读评价表

### F5 下单与担保支付
- **触发**：买家在物品详情页点击「立即购买」。
- **过程**：系统读物品表校验状态=在售、当前持有人≠买家，读用户表校验认证、信用与余额 → 买家确认订单：选择交付方式（面交/自提），自提时读自提点表选择站点 → 系统写订单表（交易状态=待支付），写物品表（状态=已锁定）→ 买家支付：校验余额；余额不足时进入「我的钱包」充值（输入金额 → 模拟支付 → 写用户表余额+、充值流水），返回后再次校验 → 扣款，写用户表（买家余额−）、平台账户表（托管+），并写两条支付记录（账户类型=用户/平台）→ 写订单表（交易状态=待交付），物品保持「已锁定」。
- **结果**：订单转入待交付，物品保持「已锁定」。
- **表格**: 物品表、用户表、自提点表、订单表、支付记录表、平台账户表
- **提示**: 1.下单前读物品表（状态/当前持有人）、用户表（认证/信用/余额）
            2.选择自提时读自提点表（站点列表）
            3.建单写订单表（待支付）、物品表（已锁定）
            4.支付写用户表（买家余额−）、平台账户表（托管+），并写两条支付记录：账户类型=用户、账户类型=平台（托管+）
            5.支付成功写订单表（交易状态=待交付）
            6.30 秒未支付：定时任务读订单表扫描，写订单表（已取消）、物品表（在售），不写支付记录
            7.托管款留在平台账户表，等 F6 完成后再放款
            8.余额不足时先进入钱包充值：写用户表（余额+）与支付记录（类型=充值、订单号为空、账户类型=用户、账户标识=用户号），充值不进入平台托管
            9.充值仅模拟、不可提现；单次设上限；充值流水只增不改，外部单号唯一

### F6 履约交付与交易完成
- **触发**：订单交易状态进入「待交付」。
- **过程**：卖家读订单表查看订单与交付方式 → 面交：双方约定时间地点，写交付记录表（约定时间、面交地点）；见面扫码核验，写交付记录表（核验时间），写订单表（交易状态=待确认）→ 自提：卖家送件入库，写交付记录表（入库时间、取件码、自提点号）；买家取件，写交付记录表（出库时间），写订单表（交易状态=待确认）→ 买家确认收货（或 10 分钟超时自动确认）→ 写订单表（交易状态=已完成）、物品表（状态=已完成）→ 系统放款：写平台账户表（托管−）、用户表（卖家余额+），并写两条支付记录（账户类型=平台/用户）→ 写履历记录表（成交事件、新主人、寄语）→ 写信用记录表（双方 +2）、用户表（信用分）→ 写通知表（订单完成，通知双方）。
- **结果**：订单与物品转「已完成」，用户可进入 F7 的评价环节。
- **表格**: 订单表、交付记录表、物品表、平台账户表、履历记录表、信用记录表、用户表、通知表、悬赏单表
- **提示**: 1.查看订单读订单表
            2.面交写交付记录表（约定/核验）；自提写交付记录表（入库/取件码/出库）
            3.交付完成写订单表（交易状态=待确认）
            4.确认收货写订单表（已完成）、物品表（已完成）；读订单表取金额与买卖双方
            5.放款写平台账户表（托管−）、用户表（卖家余额+），并写两条支付记录：账户类型=平台（托管−）、账户类型=用户（卖家余额+）
            6.写履历记录表（成交）与信用记录表（双方 +2），同步用户表信用分
            7.写通知表（订单完成）
            8.超时自动确认由定时任务读订单表扫描后写入
            9.若订单来源悬赏号非空，写悬赏单表（状态=已成交）

### F7 评价
- **触发**：交易状态为「已完成」。
- **过程**：订单完成后开启 10 分钟评价窗口，双方在「我的评价」读订单表查看待评价订单 → 提交评分、标签、内容，写评价表（状态=有效）→ 双方评完或窗口结束，评价展示 → 超时未评价：定时任务读订单表与评价表，写评价表（状态=系统默认，不计分）→ 退款成立时由 F8 写评价表（状态=作废）。
- **结果**：物品可再次流转；评价只影响展示（在个人中心交易记录中查看），不改变履历与信用。
- **表格**: 评价表、订单表
- **提示**: 1.查看待评价订单读订单表
            2.提交评价写评价表（状态=有效）；一单一评，唯一约束 (订单号, 评价人)
            3.超时任务读订单表、评价表，写评价表（状态=系统默认）
            4.评价不改履历与信用
            5.售后成立时由 F8 写评价表（状态=作废）

### F8 退款与纠纷仲裁
- **触发**：买家申请退款，或收货后 5 分钟内主张「描述不符」。
- **过程**：买家读订单表选择订单，提交退款原因与举证，写订单表（售后状态=退款中）→ 按交易状态分流：
  - 待交付（未发货）：直接退款，写平台账户表（托管−）、用户表（买家余额+），并写两条支付记录（账户类型=平台/用户）、订单表（售后=已退款）、物品表（在售）；
  - 待确认（已发货）：卖家自申请起 2 分钟内响应，同意或超时 → 按上一条退款；拒绝 → 仲裁；
  - 已完成（售后 5 分钟内）：卖家自申请起 2 分钟内响应，同意或超时 → 从卖家余额扣回，写用户表（卖家余额−、买家余额+），并写两条支付记录（账户类型=用户，卖家/买家）、订单表（售后=已退款）、物品表（在售）、履历记录表（退货）、评价表（作废）、信用记录表（回滚）并同步用户表信用分；拒绝 → 仲裁。
  → 卖家拒绝时写订单表（售后=仲裁中）、仲裁申请表（待处理）、通知表（类型=仲裁受理），转 F12 受理；退款/回滚与售后恢复由 F12 按裁定执行。
- **结果**：退款或驳回，并按责任调整信用。
- **表格**: 订单表、支付记录表、平台账户表、用户表、信用记录表、仲裁申请表、物品表、履历记录表、评价表、通知表
- **提示**: 1.选择订单读订单表
            2.申请退款写订单表（售后状态=退款中），交易状态不变；退款成功后写通知表（类型=售后结果）；仲裁驳回由 F12 写通知表（类型=仲裁结果）
            3.退款写两条支付记录（买家/平台）并更新平台账户表；售后扣回写两条（卖家/买家，账户类型=用户），不经过平台账户
            4.已发货/已完成需卖家响应，2 分钟内未响应视为同意
            5.已完成售后成立时写物品表（回在售）、履历记录表（退货）、评价表（作废）、信用记录表（回滚）
            6.仲裁驳回由 F12 写订单表（售后状态=无），交易状态保持原值
            7.收货后 5 分钟内可主张「描述不符」，超时不再受理
            8.卖家拒绝转仲裁时，写通知表（类型=仲裁受理）

### F9 求购与悬赏
- **触发**：买家搜不到想要的物品。
- **过程**：买家发布求购（分类、关键词、预算、成色、有效期），系统读物品表匹配在售物品 → 有匹配：直接展示列表，买家选择后转 F5 下单 → 无匹配：写悬赏单表（状态=悬赏中），进入悬赏大厅 → 卖家读悬赏单表浏览需求，按需发布物品（F3）→ 物品上架后系统读悬赏单表与物品表，按分类/关键词/价格容差 ±20% 匹配，命中写通知表（通知买家）→ 买家从通知查看物品并下单，订单完成时由 F6 写悬赏单表（状态=已成交）→ 到期或关闭写悬赏单表（状态=已过期/已关闭）。
- **结果**：卖家上架命中悬赏后通知买家，买家下单；否则悬赏到期关闭。
- **表格**: 物品表、悬赏单表、分类表、通知表
- **提示**: 1.发布求购读分类表选择分类、读物品表匹配；未匹配写悬赏单表（悬赏中）
            2.匹配命中读悬赏单表、物品表，写通知表（通知买家）
            3.关闭/过期写悬赏单表（状态）；成交由 F6 在订单完成时写
            4.价格容差默认 ±20%
            5.同一买家最多 3 条「悬赏中」
            6.悬赏大厅不展示买家身份

### F10 物品接力（再次上架）
- **触发**：持有人在「我买到的 / 我的物品」中点击「再次上架」。
- **过程**：系统读订单表确认该用户购买过此物品，读物品表确认当前持有人与状态=已完成 → 复用原物品编号，将旧图片状态改为「历史」（写物品图片表，不删除记录），再更新成色、价格并插入新图片（状态=有效）、标记首图，物品状态=待审核 → 运营审核（F12）→ 审核通过写物品表（在售、上架时间）、通知表 → 成交后由 F6 写履历记录表（转手）并变更持有人。
- **结果**：同一物品进入下一轮流转；成交后履历追加「转手」，持有人变更、流转次数加一。
- **表格**: 订单表、物品表、履历记录表
- **提示**: 1.读订单表确认购买关系，读物品表确认当前持有人与状态=已完成
            2.先将该物品原有图片状态改为「历史」（写物品图片表，保留记录），再插入新图片（状态=有效）与首图；同时写物品表更新信息、状态=待审核
            3.审核通过写物品表（在售）；驳回写物品表（驳回）；审核结果通知由 F12 写
            4.成交履历由 F6 写，F10 只读取履历展示接力次数，不重复写
            5.再次上架复用原物品编号，不生成新编号

### F11 三方置换
- **触发**：学生希望以物换物而非买卖。
- **过程**：学生提交置换意向（我的物品 + 指定期望物品或分类/关键词条件），写置换意向表 → 系统读置换意向表、物品表、用户表构建有向图，寻找二人互换或三人环，校验物品状态、持有人与信用 → 命中后写物品表（三方物品置「已锁定」），写置换方案表（状态=待确认、确认截止时间），写通知表（通知三方）→ 三方 10 分钟内全部确认：写置换方案表（已生效），写订单表（3 张置换单，类型=置换、金额 0、方案号=当前方案、交付方式=面交、交易状态=待交付），线下面交后写订单表（交易状态=已完成、完成时间）、物品表（状态=已完成、归属变更）、履历记录表（置换事件）、置换方案表（已完成）→ 任一拒绝或超时：写置换方案表（已作废）、物品表（解锁回在售）、通知表。
- **结果**：线下面交，更新物品归属与履历。
- **表格**: 置换意向表、置换方案表、物品表、履历记录表、订单表、用户表、通知表
- **提示**: 1.提交意向写置换意向表（可指定具体物品，也可给分类/关键词条件）
            2.匹配时读置换意向表、物品表、用户表
            3.命中后写物品表（已锁定）、置换方案表（待确认）、通知表（三方）
            4.三方确认写置换方案表（已生效）；拒绝或超时写作废并解锁物品
            5.三方确认后写 3 张置换单（待交付）；线下面交后写订单表（已完成）、物品表（已完成、归属）、履历记录表（置换）
            6.只支持 2–3 人环；方案需 10 分钟内全部确认

### F12 内容审核与仲裁处理
- **触发**：运营处理待审核物品或待处理仲裁申请。
- **过程**：运营读物品表与物品图片表查看待审核物品，核对信息、图片与分类 → 通过：写审核记录表（结论=通过），物品状态由 F3 落库（在售），写通知表（结果）；驳回：写审核记录表（结论=驳回、理由），物品状态由 F3 落库（驳回），写通知表 → 仲裁：读仲裁申请表，必要时读订单表、支付记录表、履历记录表、评价表、物品表；支持买家则执行退款/回滚（写订单表、支付记录表（按账户两条：平台/用户）、平台账户表、用户表、物品表、履历记录表、评价表、信用记录表），支持卖家则写订单表（售后=无）；写仲裁申请表（裁定结果/处理人）、通知表；按责任写用户表（信用/封禁）、信用记录表，必要时写物品表（下架）、评价表（违规删除）。
- **结果**：审核结论记入审核记录（上架或驳回由 F3 执行）；仲裁由 F12 裁定并执行退款/回滚，违规方受处罚，结果通知双方。
- **表格**: 物品表、物品图片表、订单表、支付记录表、平台账户表、履历记录表、审核记录表、仲裁申请表、通知表、用户表、信用记录表、评价表
- **提示**: 1.审核时读物品表、物品图片表，写审核记录表（结论/理由）
            2.上架/驳回的物品状态由 F3 写，F12 不重复写
            3.仲裁时读仲裁申请表，必要时读订单表、履历记录表、评价表
            4.支持买家：执行退款/回滚，写订单表（售后=已退款）、支付记录表（按账户写两条：平台/用户）、平台账户表、用户表、物品表（在售）、履历记录表（退货）、评价表（作废）、信用记录表（回滚）
            5.支持卖家：写订单表（售后=无），交易状态保持原值
            6.裁定结果写仲裁申请表（结果/处理人）、通知表
            7.处罚写用户表（信用/封禁）、信用记录表；违规内容写物品表（下架）、评价表（删除）
            8.审核与仲裁结果均写通知表

### F13 运营报表
- **触发**：运营需要复盘交易数据、处置效率或活动效果时。
- **过程**：运营进入报表页，选择统计时间范围与维度（日/周/月、品类、学院）→ 系统读订单表统计已完成订单的成交量与成交额，按账户类型=用户读支付记录表，按订单数统计退款流水与退款率，读物品表按分类统计成交分布，读履历记录表统计物品流转次数（接力），读悬赏单表统计悬赏成交与过期，读置换方案表统计置换成功率，读信用记录表统计信用变动，读审核记录表、仲裁申请表统计审核与仲裁处理量 → 结果实时汇总展示，不写入报表表。
- **结果**：形成运营报表，可按时间与维度筛选；实时统计，不保存报表记录。
- **表格**: 订单表、支付记录表、物品表、履历记录表、悬赏单表、置换方案表、信用记录表、用户表、学籍表、审核记录表、仲裁申请表
- **提示**: 1.统计成交读订单表（交易状态=已完成），按订单金额汇总
            2.统计退款率按账户类型=用户读支付记录表（类型=退款/扣回，按订单号去重）；支付订单数取支付记录表（类型=支付）的 distinct 订单号；退款率=(退款订单数+扣回订单数)/支付订单数
            3.品类分布读物品表（分类号）
            4.统计接力/流转读履历记录表（事件类型=成交/置换）
            5.悬赏与置换读悬赏单表、置换方案表（状态）
            6.学院维度读学籍表，按用户表学号关联；运营/管理员账号无学号，统计时排除
            7.审核与仲裁工作量读审核记录表、仲裁申请表
            8.报表实时计算、不落表，仅运营角色可访问

### F14 校方管理
- **触发**：学期初数据导入、学院/专业调整，或自提点变更时。
- **过程**：管理员登录（读用户表校验角色=管理员）→ 导入或更新学籍表（学号、姓名、学院、专业、年级）→ 维护分类表（新增/改名/停用，最多两级）→ 维护自提点表（名称、地址、坐标）→ 按需创建运营账号（写用户表，角色=运营）→ 保存后前台业务读取最新基础数据。
- **结果**：学籍数据、分类与自提点保持最新，为 F2 认证与前台检索提供数据。
- **表格**: 用户表、学籍表、分类表、自提点表
- **提示**: 1.登录时读用户表校验角色=管理员
            2.导入/更新写学籍表；学籍表是 F2 核验的比对源，修改会影响后续认证
            3.维护分类写分类表（最多两级）；被物品引用的分类不可删除（外键约束）
            4.维护自提点写自提点表；被订单或交付记录引用的自提点不可删除
            5.管理员不参与物品审核、仲裁与交易，审核与仲裁归运营（角色分权）
            6.基础数据变更后前台即时读取，不使用旧缓存
            7.管理员账号由初始化数据创建；运营账号由管理员在 F14 创建（写用户表，角色=运营）
